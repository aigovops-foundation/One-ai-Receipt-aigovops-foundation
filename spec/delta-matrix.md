# Delta matrix — what One Receipt takes from, gives to, and leaves alone

Non-normative until the named body accepts a mapping. Dates verified 13 September 2026 (research memos in the `practice` repo, `docs/reference/research/`). This is the document the coalition's standards liaisons are asked to review first (playbook, partner group 3).

| Adjacent work (steward, status) | One Receipt takes | One Receipt adds | Stays out of scope | Proposed contribution route |
|---|---|---|---|---|
| **IETF SCITT** — RFC 9943 architecture, RFC 9942 COSE receipts (Jun 2026) | Transparency service model; checkpoint, inclusion and consistency proofs; `rfc9942-cose-receipt` as an `inclusion_proof.format` | A registered **statement profile** for AI transaction events (the envelope as the signed statement); witness co-signatures; equivocation freeze semantics | Log internals, transport | Internet-Draft "AI Transaction Statement Profile" co-authored with SCITT editors and one log operator |
| **OVERT 1.1** (Glacis, 11 Jun 2026) | Per-action control evidence; `controls[].vocabulary: overt`; the idea of an Independent Attestation Provider | Cross-vendor envelope; SCITT registration; human mandate; disclosure; contestability object; separation of runtime seller from assessor qualifier | OVERT domains and AAL definitions (not borrowed; OR levels describe the evidence chain only) | Registered profile `one-receipt.v0` under Agentic-Extended; joint SCITT draft |
| **OpenTelemetry GenAI semantic conventions** (v1.42, Development) | `gen_ai.*` names for model, tokens, tools, agents; `runtime.otel.trace_id/span_id` | Signing and registration of the span's claims as a receipt; a mapping table `gen_ai.*` ↔ predicate fields | Stability of the conventions; sampling | PR to semantic-conventions-genai with the mapping table |
| **C2PA 2.3 / IPTC 2025.1** | Asset manifests for files; `provenance-disclosure.manifest.scheme: c2pa` | A receipt id assertion so a signed file points back to the event; provenance for text, code and voice, which carry no manifest | Manifest format | Assertion type proposal to C2PA TWG |
| **AP2, Mastercard Verifiable Intent, Visa TAP, OpenAI/Stripe ACP** | Signed intent/cart/payment mandates unchanged (`mandate.scheme`) | What the model did between intent and cart; `within_mandate` as an honest breach record; delegation inheritance | Payment rails | Liaison note; test vectors using AP2 sample mandates |
| **AIUC-1** (AIUC; quarterly; insurer-priced; UiPath a founding contributor) | `controls[].vocabulary: aiuc-1`; the periodic-certificate model | Per-call evidence that a certified control ran ("certificate-to-receipt link"); an assessor role that is not the standard's editor or the underwriter | Certification, insurance pricing | Proposal: certified agents emit receipts; shared control-id vocabulary |
| **W3C VC 2.0 / DID 1.1; SPIFFE / WIMSE; A2A Agent Cards; OpenID AIIM** | Subject, workload and agent identifiers by reference | Binding human + workload + agent + model to one event without personal identifiers | Identity issuance | Use-case submission to ITU FG-TIDA (first meeting Nov 2026) |
| **CycloneDX 1.7 ML-BOM; SPDX 3.0.1 AI; OpenSSF Model Signing** | `identity.model.bom_ref`, `weights_commitment` | The link from a model's bill of materials to the events it served | BOM formats | None needed; reference only |
| **RATS (RFC 9334); Confidential Space; PCC** | `runtime.environment.attestation` references | Honest scoping: attestation is environment-level, never answer-level | Attestation formats | None; reference only |
| **EU AI Act as amended by (EU) 2026/1744** — Art. 12 logging (prEN 18229-1 at Enquiry), Art. 26(6) six-month floor, Art. 50 (live 2 Aug 2026), Art. 73 incidents, Art. 86 explanation, Annex III 2 Dec 2027 | Retention floor; disclosure duty; explanation right; incident duty | A content-free log record pattern; the receipt id as the Art. 73 incident anchor; `contestability.explanation.legal_basis` | Legal interpretation | Comment on the prEN 18229-1 enquiry; note to the AI Office sandbox |
| **Colorado SB 26-189; California SB 942; Korea AI Basic Act; China labelling rules** | Disclosure, labelling and explanation duties; China's per-output reference number (`manifest.reference_number`) | One field set that satisfies each duty's evidence need | Compliance determinations | Regulator observers in the coalition (playbook group 10) |
| **NIST AI RMF / AI 600-1; ISO/IEC 42001, 42005, 42006; CSA AICM 1.1** | Control vocabularies for `controls[].vocabulary` | Per-event evidence a management-system audit can sample | Management-system certification | Use-case submission to the NIST AI Agent Standards Initiative |
| **OECD AIM; AIID; AIAAIC; FMF incident sharing** | Incident taxonomies | `incident` receipts that carry a hash and inclusion proof instead of prose alone | Incident databases | Liaison note |
| **AiGovOps Foundation projects** (Beacon, Umbrella, Lantern, aigovops, Replay, prompt-studio, practice) | Ed25519/JCS signing; UCID control ids; append-only log; the corpus as test vectors; the practitioner ladder | The shared envelope; see `adapters/` for each project's delta | — | This repository |

**Terminology collisions to resolve with liaisons:** "receipt" (RFC 9942 uses it for the log's proof; One Receipt uses it for the signed statement — the SCITT draft will say *statement* and *transparency receipt* precisely); "attestation" (RATS vs OVERT); "mandate" (AP2 vs plain-words rule); "witness" (SCITT vs Sigstore).
